# 0.34.0

_Released 2026-09-28._

The team page draws its featured members as the stick figures 0.33.0
introduced, from eight settings a row stores — pose, head, where the name sits,
a nudge, a scale — so a CMS edits the picture the way it edits the copy. The
vocabulary those settings are chosen from reaches `./contract`, for the hosts'
enums and constraints to bind to.

[Compare against 0.33.0 on GitHub](https://github.com/fndvit/VizVit-UI/compare/v0.33.0...v0.34.0)

## Added

- **`TeamFigure`** and **`TeamFigureField`** (`./content`) — a team member as a
  `PersonFigure`, and the featured team as a field of them between the brand
  shapes. A row's eight optional `figure*` fields on `TeamMemberData` drive the
  drawing: arm and leg pose, head mode (`cutout` / `circle` / `drawn`), which
  side and at what height the label sits, a vertical offset in px, and head
  scale and size in percent — integers, because a CMS number field is
  integer-only. All optional: a host that stores none renders the plain
  standing figure.
- **The figure vocabulary on `./contract`** — `ARM_POSES`, `LEG_POSES`,
  `HEAD_MODES`, `LABEL_SIDES`, `LABEL_ALIGNS` (with their types), and the
  `FIGURE_OFFSET` / `FIGURE_PERCENT` bounds, so a host's zod enum and CHECK
  constraint derive from the package's sets, the `PROJECT_KINDS` way. The
  drawing itself stays on `./primitives`. `ARMS` and `LEGS` are now bound to
  the tuples with `satisfies`.
- **A `record` on every card's edit map** (`TeamMemberEditMap`,
  `WeeklyEditMap`, `ProjectEditMap`, `MilestoneEditMap`, `JobEditMap`,
  `CollaboratorEditMap`): the frame's pencil, the same gesture on every card,
  and the ONE door where the host opens records — the gear goes, since the
  form holds everything the panel would, and the card's inline text goes
  plain, since a caption edited in place beside a form was two ways to change
  one thing and reached only the localized columns. A host without
  `openRecord` keeps its panels and its inline editing; page copy and chrome
  wording, which have no record, edit inline as ever.
  Both doors wear the same pencil — the panel's gear is gone from the edit
  chrome, and `edit_properties` reads «Edita: …» — so a page shows one icon
  for «edit this», whichever kind of editing is behind it.
  `TeamFigure` reads nothing else — no panel, no inline text: a caption is
  too small a place for three languages, and a panel would repeat the figure
  rows behind a second button. The host's form holds the whole person.
- **`EditAdapter.openRecord(target)`** — optional: the host's own full form for
  one row of an entity, or for a new one when `target.id` is absent. Two pieces
  of chrome read it: an `EditFrameSpec.record` puts a pencil on the frame's
  toolbar (`edit_editRecord` wording), and an `AddSlot` that names a `record`
  opens the form for a new row instead of creating a seeded one in place.
  `WhoWeArePageEdit.members` names the featured members' collection, so the
  field ends in that slot and each figure can be removed.
- **The team field is a canvas.** Wide, each featured member stands at its
  row's `figureX` / `figureY` (thousandths of the canvas width, both axes, so
  the collage scales as one piece) on its `figureZ` layer; a member with no
  position takes the next place of a centred row layout, so a host that
  stores none sees rows much as before. Narrow — a container under 40rem —
  the positions are ignored and the figures flow in order. The switch is a
  container query. New on `TeamMemberData`: `figureX`, `figureY` (null is
  unplaced) and `figureZ`; on `./contract`: `FIGURE_POSITION`, `FIGURE_LAYER`.
- **`EditAdapter.savePlacement(target, placement)`** and the **`Placeable`**
  chrome — optional: where the host implements it, each figure on the canvas
  can be dragged, nudged from its grip with the arrow keys, resized from its
  corner and sent a layer up or down, each gesture ONE patch
  (`{ x?, y?, z?, size? }`, only what changed) and so one revision.
  `EDIT_CHROME` carries it; `EditChrome.Placeable` is optional. Six
  `edit_*` messages word it (`edit_move`, `edit_moveHint`, `edit_resize`,
  `edit_bringFront`, `edit_sendBack`, `edit_placed`) and three icons draw it
  (`move`, `layer-front`, `layer-back`).
- `HEAD_SHAPES` beside the other tuples, and `figureHeadShape` on
  `TeamMemberData`: which outline a drawn head wears.
- Team-field tokens: `--vit-team-figure-base`, `--vit-team-figure-offsets`,
  `--vit-team-figure-x` / `-y` / `-z`; canvas-handle tokens:
  `--vit-placement-handles`, `--vit-placement-touch`, `--vit-placement-cursor`.

## Changed

- **The edit highlight is quiet until pointed at.** Editable text and framed
  cards used to wear a permanent dashed outline, offset outward, which weighed
  on the whole page and walked over neighbours; the highlight now shows on
  hover or focus only (a failed save stays visible), and it is drawn INSIDE
  the element's box — an inset ring on editable text, a ring layered above a
  frame's content — so the next section or card can no longer paint over and
  cut it off. The frame's toolbar sits inside its corner.
- **`CopyIntro` sets its own spacing** (`--space-4` below, none above) rather
  inheriting the host's paragraph reset, so a section intro sits the same
  distance from what follows on the site and in a CMS mirror; the mirror's
  reset had it flush against the next grid.
- **`WhoWeArePage`** renders the featured members as a `TeamFigureField`; the
  board keeps its cards. **Upgrading:** nothing required — every new field,
  map key and adapter method is optional. A host that words `EditMessages`
  itself adds `edit_editRecord` and the six canvas messages. A host passing the same `memberFor` gets the
  figure rows in the panel as soon as it supplies them, and the pencil as soon
  as its adapter implements `openRecord`.
