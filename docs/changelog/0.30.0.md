# 0.30.0

_Released 2026-09-21._

A one-line repair to the `./scrolly` surface 0.29.0 introduced: the handle type
`CrossfadeVideo` hands back through `bind:this` was not reachable through the
subpath, so a consumer could use the affordance but not name it.

[Compare against 0.29.0 on GitHub](https://github.com/fndvit/VizVit-UI/compare/v0.29.0...v0.30.0)

## Added

- **`CrossfadeVideoHandle` is exported from `./scrolly`** (#28). The type was
  declared on the component and reached
  `dist/components/scrolly/CrossfadeVideo.svelte.d.ts`, but `./scrolly` is that
  kit's whole public surface and did not carry it — and the component file is
  not itself an export subpath, so there was no path to it. A consumer doing
  `bind:this={video}` to call `replay()` had to redeclare
  `{ replay: () => void }` locally, which is a copy of a contract this package
  owns: it keeps compiling after the real one changes.

  Found consuming 0.29.0 from `natgeo-food-for-tomorrow`, which carried exactly
  that alias.

  This is a MINOR rather than a PATCH because it adds to the public surface,
  which is what the number describes here — even though the change reads as a
  fix.
