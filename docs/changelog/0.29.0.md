# 0.29.0

_Released 2026-09-21._

The `./scrolly` subpath: five scrollytelling primitives extracted from the
NatGeo "Food for Tomorrow" data story, and the first entry point that does not
re-export from the package root. Alongside it, a repair — the `user` icon that
0.28.0 shipped to npm existed only inside that tarball, never in the
repository, and would have disappeared from this release had it not been
recovered first.

[Compare against 0.27.0 on GitHub](https://github.com/fndvit/VizVit-UI/compare/v0.27.0...v0.29.0)

## Added

- **A `./scrolly` subpath, with the scrollytelling primitives** (#27). Five
  things this package did not have: `ScrollySteps`, `ScrollyStepIndicator`,
  `CrossfadeVideo`, `GlassCard` and the `stepStyle` ramp — see the
  [reference](../components/scrolly.md).
  - **`ScrollySteps` is the one mechanism**: a sticky background with a column
    of scrolling sections over it, owning the `index`/`offset` state and the
    per-step opacity/translateY ramp that every scrolly section on the site
    used to re-implement by hand. Content stays in the feature component,
    through the `background` and `step` snippets.
  - **`CrossfadeVideo` is the substance.** It expands three encodes across two
    breakpoints into the right `<source>` list, plays on visibility, and offers
    a replay affordance — four feature components in the origin project had
    each re-implemented it.
  - **These do not re-export from the package root**, which is new for this
    library. `ScrollySteps` needs an optional peer, and a subpath keeps that
    cost off every consumer that never scrollytells.
  - **The ramp is plain numbers.** `calcOpacity`, `calcTranslateY` and
    `stepStyle` have no DOM and no Svelte in them, so the animation is
    assertable in a unit test rather than only visible in a browser.
  - **Presentation is CSS custom properties, not class-name props.** The
    version this was extracted from took `activeColor="bg-[#3E2A12] ring-1 …"`
    — Tailwind strings with a brand hex baked in — so changing one colour meant
    having Tailwind and restating the whole class list.
  - Eleven tokens join `tokens.css`: `--device-h`, `--dot-*`, `--glass-*` and
    `--video-badge-*`, reusing `--space-*` and `--color-ink` where they fit.

  **Upgrading:** `ScrollySteps` needs `@sveltejs/svelte-scroller`, declared as
  an **optional** peer dependency — npm will not install it for you and will
  not warn when it is absent. Add it (`npm install @sveltejs/svelte-scroller`)
  before importing that one component; the other four and the ramp need
  nothing. A missing peer surfaces at build time as
  `Could not resolve "@sveltejs/svelte-scroller"`, not at install time.

- **A `user` glyph on `Icon`**: a head above shoulders, open strokes like every
  other glyph in the set. Named `user` rather than `person` or `account`
  because the consuming rails label the entry themselves — the glyph says who,
  not which page. It is not new to npm: 0.28.0 published it. It is new to the
  repository, and see `Fixed` for why that distinction matters.

## Fixed

- **The `user` glyph rejoins the source it was published from.** 0.28.0 went to
  npm on 2026-09-10 from a working tree that was never committed: no 0.28.0
  commit, no `v0.28.0` tag, no `gitHead` in the tarball, and `main`'s
  `Icon.svelte` still byte-identical to 0.27.0. Cutting this release from
  `main` as it stood would have quietly **removed** the glyph for anyone on
  0.28.0 — a breaking change inside a minor bump. The icon was recovered from
  the published tarball and committed, so 0.29.0 is a superset of what the
  registry already had.

- **The lockfile records the optional peer dependency.** `package.json`
  declared `@sveltejs/svelte-scroller` and `package-lock.json` did not carry
  the `peerDependencies` / `peerDependenciesMeta` entries for it, so a clean
  `npm ci` in this repository produced a tree that could not resolve the import
  and failed `ScrollySteps.svelte.test.ts` — which is the `prepublishOnly`
  gate, and therefore blocked publishing entirely.

## Other (dependencies, CI, tools…)

- `optimizeDeps.exclude` now lists `@sveltejs/svelte-scroller`. It ships raw
  `.svelte` with a `svelte` field and no `exports` condition, so Vite's
  dependency pre-bundling cannot handle it: it has to reach the Svelte plugin
  as source, or the browser test project loads a component compiled against a
  second Svelte runtime and dies on mount. Expect a
  `missing exports condition` warning from `vite-plugin-svelte` on every run —
  it is that package, and it is benign.
- The select stories demo a chosen value rather than an empty control.
- A stray `vit-foundation-ui-0.27.0.tgz` left in the repository root is gone.
